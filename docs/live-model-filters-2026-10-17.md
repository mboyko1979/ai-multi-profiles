# Updating model filters in an open chat — dev.95

Saving profile settings previously updated routes, but an admitted native session kept its last model catalog until another agent response or notification refreshed it. This affected both AI Assistant and Air. The extra excluded model was stale presentation, not another exception for historical models.

The shared router now observes the routing file and compares the previous and current client-specific list overlays against each active session's accepted agent metadata. When the visible config-option catalog changes, it publishes `config_option_update` on that session's virtual ID. The existing filter keeps the current model, removes other explicit exclusions, and retains unknown fields, groups and newly reported models. The underlying agent catalog remains intact, allowing a re-enabled model to return without discovery. Changing defaults alone does not change accepted settings. No agent requests, setters, load/resume, new sessions, history transfer or preference writes are needed. Sessions belonging to a changed agent identity are excluded from this refresh; normal recovery consent still applies. The file observer is removed on router shutdown.

This uses the existing ACP v1 config-option notification path and native client controls. It introduces no UI, catalog cache, host factory replacement or task state machine. Legacy agents exposing only `models` without config options have no equivalent ACP catalog-update notification; this change does not invent one.

Before the fix, an isolated IDEA with controlled ACP providers reproduced the same stale three-model list in both actual native SDK sessions after saving an exclusion: `build/live-filters95-baseline/assistant-live-filters.txt` and `air-live-filters.txt` show expected two, actual three. The baseline observation mode continued after recording the mismatch so both clients could be inspected; the final probe uses strict assertions.

Final native verification: `build/live-filters95-final/assistant-live-filters.txt` and `air-live-filters.txt` check exclusion, re-inclusion and repeated exclusion in admitted sessions, retaining the excluded current model and every accepted config value. Exact backend traces must remain unchanged throughout the edits, proving no provider request or session replacement. The normal native preference, preparation, profile switching, cancellation and subsequent prompt checks also run for both clients. These are controlled-provider checks, not a visual inspection of production accounts.
