# Native history and AI Multi session links

AI Assistant and Air own the local conversation transcript. AI Multi keeps the logical chat ID, profile and agent identity for each segment, provider session IDs, their order, native history references/boundaries, accepted configuration metadata and task/transfer status. Version 2 conversation records contain no user messages, assistant replies, tools, attachments or prepared transfer text. Pending profile instructions survive a restart before a session's first prompt as configuration; their body is discarded once delivered to the agent. Temporary failed-write snapshots use the same metadata-only format. Legacy records are read for compatibility and compacted when successfully updated; native history is never deleted or rebuilt from the old AI Multi copy.

Profile switching reads at most the last 20 user turns from the native client. Assistant uses SessionHistoryStorage's native singleton and flushes pending native events before reading. Air uses its current SessionProjection transcript. Only public native messages and retained attachment references are considered; hidden reasoning and raw tool output are excluded. The existing consent and size/capability checks apply before sending anything to a target provider. The selected transfer lives in memory until the native task consumes its token. A disconnected, undelivered transfer is cancelled back to its original segment and must be approved again. The native transcript stays intact.

Recovery dialogs obtain their selected text from the same native histories. The short-lived approval response contains only the explicitly selected text and is removed by the router. The IDE also removes rendezvous files when the originating router dies or the operation expires. This is transport for a consented operation, not a persistent message archive. Recovery previews conservatively estimate text size; the router performs its normal authoritative size check before creating the new provider session. Recovery transfers text; ordinary profile switching additionally offers retained native attachment references that the target can accept.

A restored chat uses its last committed profile and saved agent identity. For registered agents, an environment/model/default change does not identify a different agent and does not cause a fingerprint confirmation. Custom agents retain executable/argument identity checks. Defaults are applied only to a newly created provider session. Restore responses, settings, notifications and errors remain provider-owned; no obsolete model is guessed or replaced by AI Multi. The native client's chosen load/resume method is preserved.

If the profile was deleted, the dialog offers an available-profile dropdown, Cancel and View Local History. Local viewing does not create or load a provider session. The native transcript remains the display source, the Assistant composer/document and send actions are disabled, and Air retains its native unavailable-runtime admission. Choosing a profile later reuses the normal consented transfer. A changed agent uses the existing explicit agent-replacement dialog; its predecessor's provider session ID is never sent to it. Project Default Profile is unchanged.

Remote replay continues through the native client's requested ACP method for the bound session. Local history is the source for the combined chat and for transfers across previous segments. AI Multi does not silently contact every historical agent or replace resume with load to fetch unavailable content. If native history was removed and an agent cannot supply its portion, AI Multi does not manufacture that portion or maintain its own duplicate as a fallback.
