# Native Air composer and session icons — dev.83

The dev.79–82 profile chooser manually prepared a session and opened an acquired-thread editor. That explains both the composer moving to the bottom and the missing native Agent action: Air intentionally uses different layouts for New Session and acquired chats. The profile insertion code then appended the dropdown after settings when Agent was absent.

Air already prepares a native session behind its New Session composer. An isolated runtime inspection (`build/air83-discovery/pending-native-models.txt`) identified that session through the selected Agent action's preferences lane, Ready preferences model and `LiveThreadPreferencesSource.ref`. `AirProfileBridge` now reads that native reference and applies the existing chat-local switch to it. It verifies the selected AI Multi action, native thread identity and virtual session ID. It neither walks nor mutates the Swing tree. The manual `AirProfileChatCreator` has been removed. While Air is still preparing, the visible profile action is disabled.

The toolbar adapter inserts only the profile: after Agent when present, or before model/settings for acquired chats. Native actions, visibility, settings and layout remain Air-owned. No provider name is substituted for the AI Multi launch agent. No ACP capabilities, events or errors are synthesized.

The session list resolves its icon from an agent descriptor without a launch-target argument. The icon adapter now handles that descriptor path too. Older manually created chats have source ID `acp.ai-multi`, while native Air uses `acp.dynamic.6163702e61692d6d756c7469`. A native catalog contributor supplies a visibility-only fallback descriptor for the old source ID, delegating Air's real descriptor. It adds no launch entry or thread source and does not rewrite session records or transfer history.

The native service rejects multiple owners, so the isolated icon check failed. That alternative was removed. This is a pinned 262 adapter; the host still warns that the service is not declared overridable. The pre-existing Air `StructuredSessionViewBehavior` class-loading error is also outside this change.
