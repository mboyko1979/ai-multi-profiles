# Project instructions

- **ACP transparency is foundational**: forward the bound agent's real capabilities, client-selected methods, extension fields, notifications and errors. Translate only routing identifiers and explicitly configured profile settings. Never substitute load/resume or invent agent capabilities. Restore the last committed profile/agent segment. ACP v2 is not supported yet: negotiate protocol version 1. A changed agent identity requires an explicit recovery dialog and consent before creating a replacement session or transferring history; never send the old agent's session ID to the replacement agent.

- Plugin name: **AI Multi Profiles**. Settings entry: **AI Multi Profiles**. ACP agent name: **AI Multi**. Preserve the existing plugin ID and ACP registration ID.
- **Default Profile** belongs to the project. Selecting a profile in a chat must never change that default, including when opening a separate chat with the selected profile.
- **Launch profile selection is session-independent**: initialize a new composer's selection from the project's Default Profile and remember subsequent selection locally. Never acquire/describe/switch a live agent session merely to choose a launch profile. Avoid replacing Air application-wide factories/providers; profile bindings must be scoped to AI Multi's own composer. Native API incompatibility must not silently restore the live-session prerequisite.
- **Shared native-client architecture**: this contract applies equally to Air, AI Assistant and future IDE clients. AI Multi owns profile storage/selection, project Default Profile and profile-specific agent/environment routing. After resolving the profile, delegate agent work to the native client wherever possible, preserving the behavior of direct selection of that same agent. The second policy layer applies only configured defaults and inclusion/exclusion filters to the agent-sourced catalog; it does not become the catalog's source. The client owns its composer/chat UI, model/settings controls, loading, caches, preparation and task lifecycle. Keep shared routing/default/filter policy reusable and client-independent; host adapters only bind native launch, UI, storage and lifecycle APIs. Do not add a live-session prerequisite to cached presentation, duplicate native controls/caches or implement a second preparation/task state machine. Never add a plugin metadata cache or wrap the client's cache by profile UUID; isolation is the bound agent's native cache. Preserve profile/agent isolation, unknown protocol fields and native errors. Air changes must pass AI Assistant regression checks too; document unavoidable pinned-host adapters. See [architecture](docs/native-client-architecture.md) and [cross-client audit](docs/native-client-audit-2026-10-17.md).
- Read `.private-docs/CURRENT-INSTRUCTIONS.md` when present for project-specific standing deployment permissions. Otherwise obtain deployment authorization in the current session; preserve backups and unrelated pending updates.
- Do not restart the primary IntelliJ IDEA or interrupt active chats without separate user confirmation. Isolated `runIde` sandbox verification is authorized.
- See [deployment policy](docs/deployment-policy.md).
- Current product decisions and their implementation status: [decision log](docs/decisions.md). Keep this log current when behavior is agreed or changed.
